# Contributing to Mustry Academy projects

Thanks for your interest in improving our course materials and lab repos. These
guidelines apply to all public repositories in the Mustry-Academy organization
unless a repository has its own CONTRIBUTING file.

## Who this is for

- **Course participants** fixing a typo, clarifying an exercise step, or reporting a
  broken lab instruction
- **Alumni and the wider Ignition community** suggesting improvements that help the
  next cohort

Course hubs, slides, and curriculum content are private by default. Public
contributions usually land in lab repos, templates, and preflight tooling.

## Before you start

- **Found a bug in a lab?** Open an issue with the lab number, what you expected, and
  what happened. Include your Ignition version, OS, and whether you are on Docker or
  bare metal.
- **Have a content idea?** Open an issue first so we can discuss scope before you
  invest time in a pull request.
- **Security issue?** Do not open an issue. See our [security policy](SECURITY.md).

## Student forks and lab PRs

Most labs ask you to fork the repo and work on your own copy. That is the intended
workflow.

- Keep day-to-day lab work in **your fork**.
- Only open a pull request against the upstream Mustry-Academy repo when you are
  proposing a fix or improvement that should land for everyone (typos, broken steps,
  clearer wording, tooling fixes).
- Do not open PRs that contain completed exercise answers unless the lab explicitly
  asks for that.

## Pull requests

1. Fork the repository and create a branch from `main`.
2. Keep changes focused: one fix or improvement per pull request.
3. Match the style and conventions of the surrounding material.
4. Test your change if it touches scripts or CI, and describe how in the pull request.
5. Reference the related issue in the description if there is one.

We review pull requests as time allows. We are a consultancy first, so responses can
take a little while during busy project or teaching periods. Pinging after two weeks
is fine.
